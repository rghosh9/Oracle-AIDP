Authenticate

NOT FOR PUBLIC DISTRIBUTION: 2026-02-27

Oracle AI Data Platform Workbench requires OCI CLI authentication.

oci session authenticate --profile-name DEFAULT --region us-phoenix-1 --tenancy-name bmc_operator_access

For more information on OCI CLI authentication, see OCI CLI Token-based Authentication and OCI Request Signing.

Component Description
--profile-name DEFAULT Creates or updates the DEFAULT profile in ~/.oci/config.
--region us-phoenix-1 Sets the session region (required).
--tenancy-name bmc_operator_access Selects the tenancy by name for the session flow.

When you run the session authentication command the OCI CLI starts a browser-based sign-in flow. After successful login, CLI creates a user principal session token and associated RSA key material. Session files are saved to ~/.oci/sessions by default. You can set a different location for sessions files with --token-location. CLI writes profile entries in ~/.oci/config, including security_token_file and key_file. AidpWorkspaceClient uses SessionTokenAuthenticationDetailsProvider and RequestSigningFilter to automatically sign requests.

How this maps to API authentication

  • opc-security-token carries the session JWT.
  • Authorization: Signature ... is generated with SHA256withRSA.
  • For GET with no body, signed headers include (request-target) date host.
  • These values must match the actual request exactly.
Canonical example:
(request-target): get /20240831/aiDataPlatforms/<ai-dataplatform-ocid>/workspaces
date: Tue, 17 Feb 2026 18:20:00 GMT
host: aidpdev2.us-phoenix-1.oci.oc-test.com

Best Practices

Use manual signing only for deep debugging.

DATE_VALUE="$(LC_ALL=C date -u '+%a, %d %b %Y %H:%M:%S GMT')"
SIGNING_STRING="(request-target): get /20240831/aiDataPlatforms/<ai-dataplatform-ocid>/workspaces
date: ${DATE_VALUE}
host: aidpdev2.us-phoenix-1.oci.oc-test.com"

SIGNATURE_B64="$(printf '%s' "$SIGNING_STRING" | openssl dgst -sha256 -sign <private-key-file> | openssl base64 -A)"
Follow credential security best practices:
  • Never commit token or key files.
  • Restrict file permissions on <token-file> and <private-key-file>.
  • Rotate credentials regularly.
  • Apply least-privilege IAM policies.
