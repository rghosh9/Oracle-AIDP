Quick Start

NOT FOR PUBLIC DISTRIBUTION: 2026-02-27

Use the information in this topic to help you get started with Oracle AI Data Platform Workbench.

Task 1: Create an OCI CLI session (recommended first step)

oci session authenticate --profile-name DEFAULT --region us-phoenix-1 --tenancy-name bmc_operator_access

This command opens a browser login flow, then creates a local session token and key pair that the sample can use for signed API calls.

Task 2: Verify the generated session files and profile configuration

ls -l ~/.oci/sessions/DEFAULT/token ~/.oci/sessions/DEFAULT/oci_api_key.pem
grep -E "^\[DEFAULT\]|^region=|^security_token_file=|^key_file=" ~/.oci/config

Task 3: Set endpoint and AI Data Platform OCID

export AIDP_ENDPOINT="https://aidpdev2.us-phoenix-1.oci.oc-test.com"
export API_VERSION="20240831"
export AI_DATAPLATFORM_OCID="<ai-dataplatform-ocid>"

Task 4: Update AidpWorkspaceClient.java constants 

private static final String TOKEN_FILE_PATH = System.getProperty("user.home") + "/.oci/sessions/DEFAULT/token";
private static final Region REGION = Region.US_PHOENIX_1;
private static final String TENANT_OCID = "<tenancy-ocid>";
private static final String AIDP_OCID = System.getenv().getOrDefault("AI_DATAPLATFORM_OCID", "<ai-dataplatform-ocid>");
private static final String AIDP_ENDPOINT = System.getenv().getOrDefault("AIDP_ENDPOINT", "https://aidpdev2.us-phoenix-1.oci.oc-test.com");
private static final String API_VERSION = System.getenv().getOrDefault("API_VERSION", "20240831");
private static String buildWorkspacesBaseUrl() {  return String.format("%s/%s/aiDataPlatforms/%s/workspaces", AIDP_ENDPOINT, API_VERSION, AIDP_OCID); }

Task 5: Build and run

mvn -DskipTests clean compile
mvn -DskipTests -Dexec.mainClass=org.example.AidpWorkspaceClient exec:java

Task 5: Validate successful output

A successful run typically prints:

  • === List workspaces === with Status: 200
  • === Create workspace === with Status: 2xx and a workspace key in the body
  • === Get workspace ... ===, === Update workspace ... ===, and === Delete workspace ... === with Status: 2xx
Common outcomes from unsuccessful runs include:
  • 401 Unauthorized: expired session token, wrong token/key pair, or signature mismatch.
  • 403 Forbidden: authenticated caller lacks permission for this AI Data Platform.
  • 404 Not Found: wrong OCID, wrong API version, or wrong route shape.
  • 429 / 500: throttling or transient server issues (client retries with exponential backoff).

Troubleshooting

If your build run is unsuccessful, you can try one or more of the following methods to troubleshoot:
  • Rerun oci session authenticate if token is expired or missing.
  • Ensure the DEFAULT profile in ~/.oci/config points to the same token/key files used by the session.
  • Confirm TENANT_OCID, REGION, endpoint host, API version, and AI Data Platform Workbench OCID belong to the same environment.
  • If your deployed route uses a different resource segment, update buildWorkspacesBaseUrl() accordingly.
  • For repeated 429/500, reduce request rate and retry after backoff.

Sample Code

Minimal authentication and signed client setup from the Java sample:

RequestSigningFilter requestSigningFilter =
        RequestSigningFilter.fromAuthProvider(SessionTokenAuthenticationDetailsProvider
                .builder()
                .region(REGION)
                .tenantId(TENANT_OCID)
                .sessionTokenFilePath(TOKEN_FILE_PATH)
                .build());

String workspacesUrl = String.format("%s/%s/aiDataPlatforms/%s/workspaces", AIDP_ENDPOINT, API_VERSION, AIDP_OCID);

try (HttpClient client = JerseyHttpProvider.getInstance()
        .newBuilder()
        .registerRequestInterceptor(Priorities.AUTHENTICATION, requestSigningFilter)
        .baseUri(URI.create(workspacesUrl))
        .build()) {
    listWorkspaces(client);
}
